# 多标签内存检查（2026-10-12）

在 macOS arm64 使用真实 Fyne/OpenGL 窗口、独立临时工作区及合成数据测量；不读取用户连接、凭据或业务结果，不连接 SSH，不使用浏览器。临时诊断程序和样本保存在 `/tmp/SuperLink-tabs-memory-fixture-source` 与下表目录。应用不包含诊断代码，也不强制定时 GC。

## 原因与修改

- `vt.NewEmulator` 为每个终端分配 4 MiB ANSI 数据缓冲，并保留两个屏幕、最多 1000 行历史。这是仍在打开的会话的必要独立状态；当前未修改第三方终端协议和缓冲上限。
- Shell 使用没有显示出来的 DocTabs 管理标签，又自行绘制另一套标签条和内容；监控也使用了隐藏 AppTabs。改用不创建渲染器、不参与布局的 `documents` 模型。
- Shell 每次切换都重建整个页面、全部标签按钮和工具栏。改为复用页面和按钮，按实际变化刷新；关闭时清除按钮回调（包括同时进行的菜单功能新增回调）。
- 关闭终端主动释放模拟器和画布对象；结束但尚未关闭的会话仍保留最后屏幕。读取工作线程先捕获模拟器、取消回调先捕获线程安全管道，避免关闭后取空模拟器或读写竞态。
- 后台终端继续解析输出，但不构建不可见画面。恢复时刷新最新屏幕。无样式的空行和行尾空白不创建文字纹理；带背景、下划线等样式的空白保留。
- SQL 虚拟表格每个文本单元格原先预建 Entry、Check、Select，并在布局时生成这些隐藏控件的渲染器。改为首次编辑、显示布尔值/选择列、显示枚举时才创建；虚拟化复用时保留已创建的控件与编辑草稿。

## 测量

数值为 MiB，physical footprint 为系统进程占用；存活 Go 堆为诊断结束时手动 GC 后的值。系统 footprint 包含原生纹理及 Go 的可复用空闲页，所以关闭标签不会保证立刻恢复启动时的系统占用。

| 场景 | 修改前 footprint / 存活堆 | 修改后 footprint / 存活堆 | 样本目录后缀 |
| --- | --- | --- | --- |
| 10 个 Shell 标签，每个合成终端及监控；切换 2 轮；40 秒 | 265.9 / 122.0 | 190.2 / 115.0 | `open-before-v2` / `open-after-v4` |
| 同样 10 个 Shell 标签，36 秒关闭全部，48 秒采样 | 279.4 / 122.9 | 211.9 / 62.3 | `close-before-v2` / `close-after-v4` |
| 10 个 SQL 表标签，各 100 行、10 列短文本；切换 5 轮；40 秒 | 352.7 / 129.3 | 229.0 / 77.9 | `sql-open` / `sql-lazy-open` |

样本路径前缀：`/tmp/SuperLink-tabs-`。前后使用相同字体配置与数据；未把此前中文备用字体优化算入本次差值。第一个 Shell 试验切换 50 轮导致任务超过采样截止，未作为关闭完成后的数据使用；改为两轮后确认关闭结束、工作线程计数下降。

## 回归覆盖

- 重复切换、重命名、关闭标签时保留页面/按钮实例与正确选择；清除过期回调、关闭最后一页恢复欢迎页。
- 结束会话保留屏幕，关闭页释放模拟器/文字对象并退出读取线程；晚到的焦点/布局事件无崩溃。
- 隐藏终端保留输出，恢复显示最新屏幕；纯空行不生成文字，带样式空格仍渲染。
- 普通文本不创建编辑器/复选框/下拉框；复用布尔与选择框、编辑草稿、只读列、编辑失焦、非法值校验、虚拟化换行保持原有行为。

验证：`go test ./...`、`go vet ./...`、架构检查、源码长度检查、Fyne 来源完整性检查、macOS 原生构建。功能相关 UI race 检查（编辑/虚拟化、类型下拉、标签复用/关闭、终端输入/滚动、监控及标签菜单）通过；最新代码已自动重启，运行二进制与验证构建的 SHA-256 相同。

额外启动的全量 UI race 检查在约 5 分钟后主动停止，未计入通过项。macOS `sample` 定位到既有 Fyne 过期主题缓存清理：`TestShellFileRowPaintedContentIsVerticallyAligned` 截图触发 `cache.Clean`，大量已过期 ThemeOverride 各自调用 `RemoveThemeOverrides` 遍历全局缓存；竞态检测显著放大该清理成本。本次没有修改这一第三方缓存算法。普通全量测试及相关 race 测试均通过。Windows/Linux 本次未进行原生运行测量。
