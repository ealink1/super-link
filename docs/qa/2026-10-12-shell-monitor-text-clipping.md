# 监控数字末尾裁切修复

截图中的 IP、运行时间及百分比末尾仍有少量裁切。原因是监控主题使用 SF Mono 绘制，但 Fyne 文本宽度测量使用全局 Courier 字体，生成的字形纹理小于实际文字；增加标签边距不能补回纹理中已经裁掉的像素。

监控等宽标签改为在 `canvas.Text` 上明确指定字体资源，尺寸测量、布局、省略及绘制统一使用该资源。IP/用户名徽章的最小宽度也使用同一字体测量，保留目前的小字号及卡片布局。此次不修改第三方 Fyne。

`TestMonitorNumericGlyphsMatchTheirMeasuredFont` 使用截图中的 `28.1%`、`70%`、`54%`、`105h 42m` 和 `192.168.0.104`，将实际字形像素与明确指定字体的完整文本对照，覆盖 1、1.25、1.5、2 倍缩放。修复前 CPU、内存和 IP 少约 1 像素，运行时间少约 2 像素；修复后对比通过。另检查标签边距，以及 IPv4、IPv6、运行时间、百分比和中文在窄宽度下的 UTF-8 省略。

完整监控面板已进行浅色及深色软件渲染检查。未使用浏览器测试。

相关监控 UI 测试及竞态检查、静态检查、架构/文件长度检查、macOS 原生构建和应用包签名校验通过。本地二进制、项目应用包及 `/Applications/SuperLink.app` 已更新并核对二进制一致，最新应用启动健康握手通过。

隔离原生烟测的启动、SQLite 安装及工作区单实例检查已通过，但 SIGTERM 退出时发现输入法定时回调在 GLFW 关闭后调用 `GetCocoaWindow`，退出码为 2。该路径不涉及本次监控文字修改，未在本次处理；因此不将完整退出烟测标为通过。

额外执行的 `go test -race ./internal/ui` 在默认 10 分钟上限超时，终止时正在 `TestShellEditorRetainsCredentialsAndMetadata` 的窗口初始化/SVG 绘制阶段，不能标为全量竞态检查通过。本次相关的 `go test -race ./internal/ui -run 'TestMonitor|TestShellMetric' -count=1` 已通过。

后续用户截图指出内存 `76%` 和磁盘 `80%` 的百分号仍有缺口。原生 OpenGL 使用四舍五入后的纹理宽度，SF Mono 小字号百分号的末尾墨迹可以超出该宽度；此前软件测试的参照也是 Fyne 文本纹理，不能独立确认完整字形。

等宽标签绘制时增加一个不可见的尾部空格，为末尾字形提供纹理留白；可见值和无障碍文字保持原值。省略逻辑预留该空白，徽章宽度测量同步更新。新的 `TestMonitorPercentageFitsRoundedOpenGLTexture` 直接将字体画入加宽画布，检查是否有墨迹落在 OpenGL 的取整纹理宽度之外。移除末尾空格的对照在 `76%`、1 倍缩放下失败：20 像素宽的纹理丢失 x=20 处墨迹。

原生检查使用当前生产标签源码构建独立小窗口，三列分别绘制旧的不留白文字、修复后的控件、留白的完整字形参照。在 1、1.5、2 倍缩放下，修复后的 `76%`、`80%`、`100%` 均与完整参照逐像素相同。在 1 倍缩放下，前两者旧图分别有 79/101 个墨迹像素，修复及参照分别有 83/105 个，验证补回缺失像素。原生截图保留在本地 `.cache/shell-qa/percent-native/production*.png`。

追加的纹理回归、监控相关竞态测试、静态检查和 macOS 原生构建通过。已替换本地二进制、项目应用包及安装应用包，校验签名与二进制一致并重启，启动健康握手通过。此次仍未使用浏览器测试。
