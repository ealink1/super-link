# 中文文字底部裁切验证（2026-10-13）

## 原因与修复

Fyne 的 `walkString` 绘制时使用所有实际字形分段的最大 ascent，但测量高度与返回的基线仍来自主字体的空格。Arial、DejaVu 与紧凑 CFF 中文回退的行指标不同，导致笔记正文、标题及普通控件中的中文纹理高度不足。

现在测量高度包含实际使用字体的 ascent、descent 与 gap，返回基线与绘制基线一致；空白、制表符与纯英文保留主字体指标。移除监控标题此前补偿错误行高的字体专用位置偏移，原有图标与文字对齐测试容差未调整。没有更换中文资源或撤销字体按需解析。

## 验证

- `TestChineseTextInkFitsMeasuredLine` 使用独立 Harfbuzz 分段及超大栅格，避免 Fyne 截图重复应用同一个裁切错误。覆盖 5 种字体样式、9 种字号、4 组中文/中英混排、5 种缩放，共 900 组字形栅格检查。修复前真实失败，修复后全部通过。
- Fyne 新增 `TestFallbackLineMetricsCoverUsedFacesAndMatchDrawingBaseline`，检查混排高度覆盖各回退分段、测量与绘制基线一致、解析回退后纯英文尺寸稳定，以及空字符串/制表符保留主字体行指标。
- 原生 macOS OpenGL 对比使用生产 `Theme` 与生产中文资源。左列走普通主题回退，右列显式使用完整中文字体作为参考；对照程序通过 Go 源码覆盖恢复旧 `font.go`，其余代码一致。测试内容均为无敏感信息的通用中文。
- 1、1.5、2 倍缩放下，10/13/16/26/32 号字共 15 组。旧代码 14 组丢失底部像素；修复后 15 组的上下字形边界全部与参考相同，墨迹像素数差异均小于 0.3%。32 号粗体在 2 倍缩放下，修复前底部边界为 83，参考为 89，修复后为 89。
- 原生截图、对照程序及像素统计保存在本地忽略目录 `.cache/chinese-metrics/`。未将用户截图中的笔记内容复制到测试或日志。
- 使用 DejaVu 2.37 字体的独立 Go 源码覆盖测试也通过，包含中文行指标及监控图标对齐；这不能替代 Linux 原生图形验收。
- 全量 `go test ./...`、`go vet ./...`、源码尺寸与架构检查、Fyne 来源/补丁及 UI 资产校验通过。
- 相关 UI 竞态测试（中文栅格、中文菜单、富文本笔记、监控对齐/悬停）以及 Fyne painter/cache 全套竞态测试通过。
- 未使用浏览器测试；其他操作系统的原生图形界面未在本次本机修复中人工验收。
