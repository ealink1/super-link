# 长 SQL 编辑区尺寸修复

用户报告粘贴长 SQL 后窗口被撑大、结果区被挤出。原因是行号使用 `ScrollNone`，其最小尺寸继承整段行号文本的高度，`SetMinSize` 在该方向下不生效。

保留原有编辑器的文本、IME、选择、撤销及滚动行为，为行号滚动对象增加固定宽度、零最小高度的可见区域布局。正文仍由编辑器内部滚动，行号仍同步同一垂直偏移，不单独增加滚动条。查询/结果分栏的最小高度不再随 SQL 行数增长。

验证长多行 SQL 与超长单行、开启/关闭换行、大小窗口的分栏尺寸及结果区可见性；验证正文和行号滚动同步、编辑内容不变；用原生 macOS 窗口复现修复前后，再完成相关测试、静态检查与构建重启。不使用浏览器。

同时避免对嵌入的 Entry 和 codeEntry 分别创建主题容器，防止生成两个不同的滚动对象；在渲染布局和刷新后同步行号偏移，覆盖光标自动滚动与窗口调整。
