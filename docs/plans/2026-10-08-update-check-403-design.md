# SuperLink 更新检查 403 修复

## 问题与证据

用户在 0.1.2 的检查更新窗口遇到 `Release HTTP 403`。
现有客户端只请求 GitHub REST latest API，任意非 200 响应只显示状态码。
2026-10-08 命令行读取同一 API，返回 403，`X-RateLimit-Remaining: 0`、
`X-RateLimit-Limit: 60`，确认本机当前出口的匿名 API 配额耗尽。
GitHub 官方 `/releases/latest` 返回 302 到仓库 Release 列表，当前没有公开稳定版。
此证据不能证明用户截图时的出口与本机出口相同，但复现了同类错误。

## 方案

继续以 REST API 为主；仅在默认仓库 API 返回 403/429 时，使用 GitHub 官方
`/releases/latest` 入口解析稳定版本标签。两个签名文件固定下载该标签下的版本，
避免发布切换导致清单和签名来自不同版本。无需额外令牌，也不增加第三方镜像。

只接受同仓库、无凭据、无查询参数的 HTTPS 标签跳转，并校验稳定语义版本。
沿用 Ed25519 签名、标签与清单版本绑定、stable 渠道、可信下载域名、资源大小上限、
下载 SHA256 及上下文取消机制。不读取草稿或预发布，不修改现有 Release 或标签。

限流和拒绝访问分别显示中文原因及网络/代理重试提示；没有公开稳定版时显示说明。
缺失清单文件的 404 与仓库没有公开发布的 404 分开处理。
不读取或显示 HTTP 错误正文，避免代理错误页或下载地址泄露敏感内容。
