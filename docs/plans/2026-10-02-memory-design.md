# SuperLink 内存修复设计

用户观察到 QA 主进程占用 618.3 MB。目标是定位实际对象，减少无用常驻内存，保留 SuperLink 复刻界面、中文覆盖、原生输入、查询与驱动隔离。

1. 用 macOS `vmmap` / `footprint` 区分运行时、压缩页、图形缓冲和驱动进程；以隔离工作区的原生 Fyne 窗口采集 Go 堆，记录 GC 前后数据。
2. 完整中文 TrueType 字体按多个主题范围重复解析。采用内容指纹共享解析结果，限制缓存容量；以最小、可验证的本地 Fyne 补丁实现，不修改用户 Go 模块缓存。
3. 改用完整 OpenType/CFF 轮廓，使未显示字符不再预先展开全部 TrueType 点数组。保持字符映射、字形顺序、字宽；不以删减中文字符降低内存。
4. 系统语言字体只在现有字体缺字时加载，保留语言与 Unicode 回退。结果标签复用按钮与主题对象，删除已移除标签的引用。
5. 验证中文、字宽、原生编辑器、结果选择、深浅主题、字体缓存并发与淘汰；运行单测、竞争检测、静态检查、原生对照及应用打包。

不采用周期强制 GC 作为产品修复，不降低 Retina 分辨率，不移除界面功能。诊断程序的最后一次 GC 只用于区分存活对象和回收余量；实际进程对比使用它之前的数值。

代价：CFF 字体文件略大，仓库保留一个固定版本的 Fyne 副本及三文件补丁。后续升级必须重核补丁和字体回退行为。图形缓冲、大结果、更多标签和首次使用未覆盖文字仍会增加内存；本次不承诺固定内存上限。
