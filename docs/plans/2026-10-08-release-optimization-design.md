# SuperLink 发布耗时优化

用户同意优化发布流程。v0.1.5 的 Release 工作流耗时约 13 分钟：最慢平台为
Windows ARM64（532 秒），汇总上传阶段为 223 秒。每次界面调整也会重新编译并
上传六个平台共 131 个独立驱动；主分支和版本标签还会重复触发普通 CI。

## 发布模式

只包含 `internal/ui/`、`internal/branding/`、`docs/` 或 `README.md` 修改的版本，
允许复用最新公开稳定应用版本所引用的驱动。通过公开版本标签解析基础提交，
要求其为目标提交的祖先；Git diff 禁用重命名识别，避免移出驱动目录的文件漏检。
任何驱动、领域、运行时、依赖、构建工具或工作流变化，仍执行完整驱动构建。
本次发布工具自身的变化属于完整构建，后续纯界面或文档版本才能使用快速路径。

复用前验证旧清单的 Ed25519 签名、公钥、较早稳定版本、完整平台库存、固定驱动
仓库地址及远端资产的大小、SHA256 digest。基础标签的本地提交须匹配 GitHub
公开标签提交。无法确认基线时，准备阶段自动回退完整构建。

驱动记录保留原文件名、版本下载地址、哈希、协议及 revision；不将旧文件重新
命名为新版本。新应用更新清单仍包含六应用及 131 驱动，客户端协议保持兼容。
应用基础版本和驱动版本分开记录，因此允许连续多个界面版本复用同一驱动版本。

## 构建与发布

六个平台继续执行原生测试、应用构建、SQLite 协议探测、离线 SQLite 打包、安装
程序生成和烟雾验证。快速路径只省略独立驱动编译及上传；离线 SQLite 每次新建。
各平台 metadata 带来源提交，与复用证明一致。签名工具独立认证旧签名及公钥，
拒绝任何改变或缺失的旧驱动记录，新应用二进制仍检查实际长度与哈希。

准备阶段生成有大小限制的三份证明文件，通过 Actions artifact 传给各构建任务。
汇总阶段接受完整复用证明，但不上传它们。复用版本只新建应用发布；不会创建、
公开或修改驱动仓库版本。发布前再次验证远端驱动仍完整可用，发布说明链接实际
驱动版本。完整构建维持原先两仓草稿、上传校验及先驱动后应用的发布顺序。

普通 CI 只接受分支推送和 PR，版本标签由 Release 的原生检查覆盖。Go 模块与
编译缓存按系统、架构、Go 版本、依赖哈希、应用/完整构建模式隔离，并允许复用
前一提交的缓存。Windows x64 缓存固定 GCC 15 下载包，每次仍校验既有 SHA256。
Windows ARM64 的 MSYS2 继续使用其内置缓存。

## 验证与边界

26 项 Python 发布契约测试（包含原完整发布路径）通过；Go 签名与基础清单测试、
race 检查、go vet、actionlint、架构与源文件大小检查通过。测试覆盖错误签名、
错误公钥、篡改驱动、遗漏驱动、提交不一致、远端 digest 不符、额外文件，以及
快速发布不对驱动仓库进行写操作。

真实 v0.1.5 签名和 131 个公开远端驱动已验证。本地 Mac ARM64 验证包使用 0.1.6
作为临时版本号，单独存于 `bin/release-optimization-check/`，未发布或安装。
macOS 原生应用、打包签名、DMG CRC 校验、复用清单校验与安装包烟雾验证通过。
没有浏览器测试。本次未提交、推送或触发发布；云端缓存命中率和提速幅度需下一次
真实发布测量，不能用本地构建时间代替六平台结果。
