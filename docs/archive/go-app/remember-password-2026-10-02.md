# “记住密码”变更与自检

> 名称与命令已于 2026-10-03 统一为 SuperLink；历史截图、产物哈希和验收结论仍对应记录当日版本，本次更名验证见 [完整更名记录](superlink-namespace-2026-10-03.md)。

日期：2026-10-02。项目：独立的 superlink；SuperLink 源仓库未修改。

## 用户行为

- 原“将凭据保存在系统钥匙串”改为“记住密码”。新连接默认勾选；编辑已有连接保持原选择。
- 按后续要求，“记住密码”和“保存后展开”置于密码输入框右侧同一行，移除原底部勾选行；勾选后保存仍会连接并展开。
- 点击“保存”后，密码及 SSH/代理/URI/DSN 等敏感字段加密保存在当前工作区，重启自动恢复。
- 点击“测试连接”不会保存密码。取消勾选并保存后，删除以前的本地密文，仅保留当前进程内存中的凭据。
- 不再调用系统钥匙串的读取、写入或删除，因此密码存储流程不再弹出电脑密码授权。
- 旧版钥匙串凭据保留，首次使用新版需要重新输入一次密码再保存；旧会话密码退出后已经丢失，也需要重新输入。

## 实现与保护边界

工作区 `credentials/master.key` 是按需生成的 32 字节随机密钥，每个凭据文件使用 AES-256-GCM。
使用 [Go 标准库的随机 nonce AEAD](https://pkg.go.dev/crypto/cipher#NewGCMWithRandomNonce)，
`local:v1:UUID` 引用作为认证附加数据，防止密文互换。SQLite 不保存密码，只保存引用和公开配置。

macOS/Linux 目录权限 0700、文件 0600；拒绝不安全权限、软链接、无效文件名和超过限制的数据。
文件先完整写入、同步，再通过排他硬链接发布；macOS/Linux 同步发布目录。元数据保存失败时
删除新密文，保留旧凭据；元数据成功后删除旧密文。Windows 继承工作区 ACL，目录 fsync 不支持，
原生 Windows 权限和持久化行为尚未验收。

密钥与密文同存本机，因此有权限读取完整工作区的同账户程序能够解密；这不等同于钥匙串隔离。
备份必须包含整个 `credentials/`。丢失密钥时不会在仍有密文的情况下自动生成替代密钥；
应恢复完整备份。无备份时，可先关闭应用、备份并移走整个损坏的 `credentials/`，之后逐个连接
重新输入密码并保存。这个恢复步骤会使全部旧本地凭据不可用，不自动执行。

降级旧版不能读取新版本地凭据；应用内更新的 SQLite 快照不等于完整密码备份。
已有钥匙串条目需用户在系统钥匙串中自行管理，新版不会静默删除。

## 保存后旧提示再次出现的修复

用户反馈勾选并保存后仍出现“密码不可用”。只读状态检查确认当前默认工作区的保存标志为 true，
引用已切换到 local:v1，引用对应的密文及 32 字节密钥文件均存在且权限正确。

原因是 `editSelected` 先弹出信息框，再打开编辑窗口。编辑窗口隐藏后，底下的旧信息框仍在，
造成刚保存成功却又被提示重新输入的假象。回归测试在旧代码上明确复现两个叠层；现在改为单个
编辑窗口中的提示，保存或取消都不留下旧弹窗，并使用读取到的最新 revision 避免旧侧栏快照保存冲突。

保存/取消、跨存储实例读取和重新编辑的回归及 race 通过；完整 UI 单测、UI vet 和体积检查通过。
最新包内文件、ZIP CRC、23 项产物的大小及 SHA256 再次通过。

原生复查：正常退出旧实例后，用同一默认工作区启动新版；通过连接菜单打开“编辑连接”，
看到密码字段恢复为掩码、“记住密码”保持勾选，没有错误提示。点击“取消”回到主窗口，也没有残留弹窗。
