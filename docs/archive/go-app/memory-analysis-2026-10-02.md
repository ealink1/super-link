## 结论

618.3 MB 主要来自界面字体重复解析、预先解析大量字形和图形缓冲。Fyne 使用原生窗口，并不自动保证低内存；本项目之前的主题与完整中文字体组合放大了这些开销。

原生欢迎页对照中，进程占用从约 **409 MiB 降到 191 MiB**；最终构建打开两个查询页后约 **266 MiB**。欢迎页 GC 后存活 Go 堆从 **254.77 MiB 降到 42.92 MiB**。进程数值使用 macOS physical footprint，包含图形和压缩页；Go 堆只是一部分。

用户截图、运行约十小时的 QA、全新欢迎页和两个查询页是不同负载，不应将它们直接当作同一场景的前后对照。上述百分比对比仅适用于相同的原生欢迎页：进程占用下降约 53%，存活 Go 堆下降约 83%。

## 原因与证据

- 截图主进程 PID 3439。首次 `vmmap` 实测 footprint 532.5 MiB、峰值 697.2 MiB；`footprint` 另一时刻为 528 MiB。未标记区域约 363 MiB；IOSurface、图形分配和 GPU 未映射内存合计约 130 MiB。不能仅凭区域名称把它全部算成 Go 堆。
- SQLite Agent PID 3499 约 13 MiB。截图中的 AutoFill 和 ThemeWidgetControlViewService 是 macOS 服务，合计约 26 MB，解释不了主进程的数百 MB。
- 原生隔离欢迎页的 `pprof` 显示约 260.62 MiB 存活采样堆，其中约 96% 与字体表、轮廓点数组、字形和字体 face 解析相关。原始 TrueType 字体每种均有 31,036 个字形。
- Fyne 原始字体缓存按文字样式和主题范围区分。同一字体在不同范围重复解析，局部主题刷新还会产生新范围。结果标签每次刷新重新建立按钮和局部主题，进一步增加缓存对象。
- 即使内置字体已经覆盖文字，原始 `lookupFaces` 也会提前加载系统语言字体。本机这条调用链在堆采样中保留约 58 MiB。
- 用户运行的 QA 可执行文件生成于 00:21，文件 SHA256 `2c18e6616a481da4dbad17bd915cc090f40a352965177ac9c4e39a98ae128d42`；它早于本次修复。版本字符串同为 0.1.0，判断是否更新必须核对构建文件。

## 修复

1. 在固定 Fyne 副本中按字体内容 SHA256 共享解析结果，最多缓存 32 个 face，FIFO 淘汰；字体内容发生变化会重新解析。并发解析用互斥锁保护。
2. 限制临时主题范围缓存到 4,096 次存储，避免刷新范围编号长期累积。淘汰后字体解析仍可复用。
3. 使用 OpenType/CFF 的紧凑字形指令，避免启动时展开所有 TrueType 轮廓点。每个字体的 30,890 个字符映射、31,036 个字形顺序和全部字宽均与之前一致；不裁减中文字符。原生渲染回退能力保留。
4. 系统语言字体延后到实际缺字时加载，优先顺序保持内置字体、语言回退、逐字回退。
5. 结果标签复用按钮和主题对象；计数、选择、重排时保留按钮身份，移除标签时删除引用。

保留复刻配色、布局、字体字宽、语法高亮、编辑器原生输入和驱动隔离。没有降低窗口分辨率，也没有在产品中加入周期强制 GC。

Fyne 副本有 2,145 个原始文件，实际补丁集中在三个字体相关文件。原文件哈希、改动哈希、BSD 许可证和可审阅 diff 保存在 `docs/fyne-source.json`、`docs/fyne-memory.patch` 和 `third_party/fyne`；`tools/verify-fyne.py` 校验代码与模块替换。

## 原生测量

`tools/memory-probe` 启动生产 `ui.New` 和实际 Fyne/OpenGL 窗口，使用新建私有工作区。它不读取用户连接、不启动浏览器、不开放 HTTP profiler。数值统一为 MiB（1,048,576 字节）。

| 阶段／场景 | GC 前 Go 堆 | GC 后存活 Go 堆 | 原生进程 footprint |
| --- | ---: | ---: | ---: |
| 修复前欢迎页 | 259.71 | 254.77 | 409.0（启动约 20 秒） |
| 共享解析后的欢迎页 | 136.64 | 129.10 | 未保留可比的直接采样 |
| 加入 CFF、尚未延后语言字体 | 96.38 | 90.35 | 257.10 |
| 最终欢迎页 | 51.67 | 42.92 | 190.94 |
| 最终两个查询页 | 78.82 | 62.05 | 265.99 |

最终欢迎页约 20 秒时为 190.72 MiB，45 秒 GC 前为 190.94 MiB。两个查询页使用只读本地 SQLite、120 条测试记录和两份恢复的 SQL 草稿；草稿不会自动执行。这是原生查询页负载测试，不是大结果集测试。20–75 秒的 footprint 约 266 MiB，采样 goroutine 稳定为 15，未观察到这一时间段内持续增长。

诊断程序结束前的单次 GC 只用来区分存活对象与回收余量。表内进程对比采用 **该 GC 之前** 的数据；产品的回收策略未改变。私有原始 JSONL 和 heap profiles 位于 `.cache/memory-qa/`，未加入 Git。

## 实际 QA 更新与检查

10:30 通过应用菜单正常退出旧 QA，确认主进程及 SQLite Agent 退出，再替换应用包；连接和草稿工作区保留，状态数据库另作本地备份。更新后的 QA PID 23605，恢复一个查询草稿时 footprint 217.70 MiB；通过电脑控制点击执行本地演示 SQLite 的常量 `SELECT`，实际显示一行三列（整数、文本和 NULL），之后测得 227.94 MiB，进程峰值 246.28 MiB。未强制 GC，未执行用户业务库写入。

电脑控制确认中文界面、语法高亮、结果标签和网格能正常显示。本次原生检查不替代完整界面复刻、中文 IME 或大结果集验收。正在运行的 QA 已是修复版，完整字体、窗口分辨率与用户工作区均保留。

`python3 tools/build.py --all-drivers --package` 和原生启动烟测通过，22 个 Agent 已生成。ZIP CRC、文件路径及包内外文件一致性检查通过；构建后的主程序 SHA256 为 `8a7ae50c23fba6c5ec2f7a04c947feb33760929acdd6ab010a03c099f6ab921b`。包 `dist/superlink_0.1.0_darwin_arm64.zip` 为 83.75 MiB，SHA256 `0aaf237dfd667f0bbe0168b0cffdfc09ae99ba77d32b3f6483fc30d1aff9d772`。CFF 资源增加了包体积，以较少的运行时轮廓解析对象换取较低内存；尚未正式发布。

## 自检与限制

- 应用全量 `go test ./...`、UI 竞争检测、`go vet ./...` 通过。
- 补丁字体解析／范围缓存的共享、并发、内容变化、淘汰、无效字体和延迟回退测试通过；Fyne painter/cache 的竞争检测通过。
- 全部 92,670 个字符映射、93,108 个字形字宽与转换前一致；字体加载测试逐一验证全部字符覆盖，校验文件摘要和参考字宽。
- 每个字体抽查 260 个拉丁／中文字符的轮廓边界；最大差异约 0.048 字体单位。CFF 控制点量化最多半个字体单位，13 px / 1000 UPEM 时低于 0.007 px；这是格式量化，不是逐像素相同的承诺。
- 编辑器输入／撤销、语法高亮、标签重排／计数／选择、深浅主题和表数据页回归通过。软件渲染截图保存在 `.cache/memory-qa/software-captures/`；它们不是电脑控制截图。
- 额外执行的 Fyne container 全套在本机有七个 DocTabs 快照测试失败；未修改的原始 v2.8.1 也出现相同七类失败，涉及未显示的 macOS 滚动条。抽取比较的六份实际 XML 完全一致。应用使用自有工作标签；仍保留这一上游验收限制，不能声称 Fyne 全套测试全部通过。
- 此次短时测量不能证明长时间运行无泄漏，也不代表所有数据库、大表或所有窗口尺寸的上限。字体回退首次加载、更多标签、Retina 图形缓冲和更多查询结果都会增加内存。现有分页、结果预算和关闭释放机制仍需在后续复杂负载中持续验证。

## 重现

先构建应用和离线 SQLite，再使用全新输出目录：

```sh
mkdir -p .cache/memory-qa
go run ./tools/memory-probe --output .cache/memory-qa/new-welcome \
  --drivers bin/SuperLink.app/Contents/Resources/drivers --duration 45s
go run ./tools/memory-probe --fixture --output .cache/memory-qa/new-queries \
  --drivers bin/SuperLink.app/Contents/Resources/drivers --duration 75s
go tool pprof -top .cache/memory-qa/new-welcome/heap.pprof
```

输出目录必须不存在，以防误打开已有工作区。`samples.jsonl` 同时记录 Go 堆和 macOS footprint；其他平台目前只记录 Go 堆。主程序必须退出旧进程并从本次构建启动，正在运行的旧 QA 不会因磁盘文件变化自动获得修复。
