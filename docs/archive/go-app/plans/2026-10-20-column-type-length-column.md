# 字段类型与长度拆分为两列

## 背景

表设计器的 `类型` 列把参数和类型名混在一起（`VARCHAR(100)`、`DECIMAL(10,2)`），既不好改长度，也没法按类型排序或比较。用户要求把长度单独拆成一列。

## 设计

设计器列顺序改为：名称 / 类型 / **长度** / 主键 / 自增 / 非空 / 默认值 / 注释。

- `类型` 列只放基础类型，下拉候选改为不带参数的基名（`VARCHAR`、`CHAR`、`DECIMAL`…），仍保留「自定义…」入口。
- `长度` 列是普通文本单元格，接受空值、`100` 或 `10,2`，其它输入回退为校验错误，不写入字段定义。
- `splitColumnType` 把 `INT(11) UNSIGNED` 拆为基名、参数、后缀三段，`joinColumnType` 原样拼回，后缀不会丢。
- 切换类型时：新类型不接受参数则清空长度；接受参数且长度为空则补默认值（VARCHAR 255 / CHAR 1 / DECIMAL 10,2）；后缀只在整数类型间保留。

所有下游仍只认 `ColumnDefinition.Type` 的完整字符串，DDL 生成、结构对比、SQL 预览均不变。

## 列宽

8 列在 960 宽的弹窗里默认 140px/列会横向溢出。`gridModel` 增加 `widths` 覆盖项，设计器按内容分配：名称 140、类型 110、长度 76、主键/自增/非空 52、默认值 120，注释列吃剩余宽度（最小 140）。

## 验证

`splitColumnType`/`joinColumnType` 往返、长度校验、类型切换默认值、列索引错位共 4 组单测通过；离屏渲染确认 8 列在 960 宽内一屏排开且 `VARCHAR/100`、`DECIMAL/10,2` 正确拆分；全量测试、vet、架构与文件长度检查通过。未使用浏览器。
