# 本地记住密码

用户要求：不再因保存、读取密码弹出电脑密码授权，使用“记住密码”的方式。

## 选择

采用本地 AES-256-GCM 加密文件。继续系统钥匙串仍可能弹窗；明文保存违反项目约束；主密码模式同样需要输入密码。因此使用随机本地密钥配合当前用户文件权限。

新连接默认勾选“记住密码”，编辑已有连接保持原选择。取消后只保存在当前进程内存中。SQLite 元数据只保存凭据引用，不包含敏感字段。每次写入创建新的密文文件，元数据成功提交后删除旧密文；失败保留旧凭据。
按后续用户要求，“记住密码”和“保存后展开”紧接密码输入框右侧，在认证行内勾选；保存后的连接与展开逻辑保持原行为。

## 文件和兼容

工作区 credentials/ 下 master.key 为 32 字节随机密钥，每个 UUID.cred 是带版本头的认证密文。凭据引用作为附加认证数据，防止两个连接的密文互换。使用 Go 标准库生成随机 nonce，密钥及文件模式 0600，目录 0700（macOS/Linux）；Windows 继承工作区 ACL，不声称已做原生权限验收。

临时文件写完并同步后通过排他硬链接发布，避免覆盖或半写密钥。拒绝路径穿越、符号链接、超大文件和非私有 Unix 权限。密钥丢失或损坏时明确报错，不自动替换仍有密文的密钥。

旧会话凭据重启后需重新输入。旧版钥匙串条目保留，不自动读取或删除，避免再次授权；首次编辑时提示重新输入并勾选记住密码。
凭据读取失败时只打开连接编辑窗口，在页内展示错误，不再额外叠放信息弹窗。恢复编辑使用此次读取到的最新连接 revision，避免侧栏旧快照导致重新保存冲突。

## 安全边界和验证

密钥与密文同在本机，可读取整个工作区的同账户程序也能解密。这是免交互本地记忆方式，不等同于钥匙串保护。备份必须包含整个 credentials 目录；仅复制 SQLite 无法恢复密码。

使用临时工作区和测试凭据验证重建存储实例后的读取、不同进程读取、更新/取消/删除、元数据失败保护、密文篡改/互换、密钥丢失、权限及符号链接。UI 验证默认勾选与已有设置保持。不访问用户的真实密码或钥匙串，不使用浏览器测试，不提交或推送。
