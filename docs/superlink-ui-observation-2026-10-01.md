## 1. 核心结论

SuperLink 的主要工作路径是：**连接 → 数据库 → 模式 / 对象分类 → 表或其他对象 → 独立工作标签页**。
查询、表数据、结构设计、导入、比较、同步和设置都有各自的页面与状态。
连接类型数量只是接入范围，不能证明这些工作流程已经对齐。

SuperLink 已补入惰性连接树、独立表数据页、筛选分页、受保护的暂存编辑、字段 / 索引设计器、查询参数与命名保存、六格式导出和文件导入。
完整功能与视觉一比一仍未完成：对象类别、专业编辑器、外键 / 触发器编辑、比较同步、快照、AI、完整设置和云备份仍有缺口。最新原生视觉复查因桌面锁定尚未完成，不能以软件渲染截图替代。

功能对齐以可完成相同任务、保留同样的上下文和反馈为目标。Fyne 的控件布局可以适应原生桌面，但不能把缺少的工作流程当作界面差异。
**JVM 管理连接器按用户要求排除**，不纳入复刻或后续验收。

## 3. 八条实际操作流程

### 3.1 新建连接与连接配置

实际路径：顶部“新建连接” → 数据源类型选择 → MySQL 参数表单 → 切换基本、网络安全、外观和高级页 → 取消。
另查看了已有连接的编辑表单，没有保存修改。状态：**页面已查看**。

| 页面 | 实际看到的内容 | Fyne 对齐重点 |
| --- | --- | --- |
| 类型选择 | 分类、搜索、最近使用、收藏入口；选择类型后进入参数表单 | 类型选择应有搜索和分类，缺驱动时直接说明解决路径 |
| 基本配置 | 名称、环境、主机、端口、用户名、密码、可选默认库、连接 URI；URI 解析 / 生成 / 复制入口 | 不填默认库仍能连接并浏览，URI 与分字段配置要明确优先级 |

实际路径：双击已连接 PostgreSQL → 展开数据库 → 展开模式 → 展开表分类 → 打开表 / 表菜单。

## 4. 页面组织对 Fyne 的要求

```text
主窗口
├─ 全局操作：新查询 / 新连接 / 分组 / 数据工作流 / SQL 工具 / 驱动 / 设置
├─ 左侧：连接 → 数据库 → 模式 → 对象分类 → 对象
└─ 工作区标签
   ├─ 查询：上下文选择 → 编辑器 → 多结果 / 日志 / 参数
   ├─ 表数据：字段元数据 → 筛选排序 → 数据网格 → 变更预览 / 提交 → 分页
   ├─ 结构设计：字段 / 索引 / 外键 / 触发器 / DDL
   └─ 工作流：导入 / 导出 / 比较 / 同步 / 快照 / 设置
```

需要保留的行为包括：从树继承准确上下文；数据页与设计页分别保存状态；正在执行或有未提交变更时关闭提示；环境保护在当前页面可见；切换标签不让后台旧请求覆盖新内容。
对象树按数据源能力显示分类，表读取与自定义查询是不同任务，不能只用“生成 SELECT”按钮代替表浏览。
大表必须有服务端分页或驱动可支持的增量读取；当前内存预算仍要保留，达到预算不能显示成完整数据。

可复用现有 Go 应用服务、凭据管理、任务取消、结果类型和虚拟表格基础。
Fyne 已新增对象树、元数据表头、条件构建器、分页控件、可编辑单元格和字段 / 索引设计页；后续每项能力继续采用明确状态模型，不能仅堆积按钮。

## 6. 后续实施与验收顺序

### 第一批：把连接到读表这条链完整打通

1. 连接树：展开连接、数据库、模式和对象；空默认库仍能使用；加载中、失败、重试可见。
2. 对象打开：双击表直接进入数据页；右键新查询继承正确上下文；重复打开与新标签行为一致。
3. 表浏览：字段类型、主键、NULL、大整数显示正确；筛选和排序作用于完整查询；分页切换不会混入旧响应。
4. 查询页：库 / 模式选择、行号、高亮、查找和格式化可用；中文输入、选择执行、取消和草稿恢复单独验证。

验收使用自建 SQLite、MySQL、PostgreSQL 测试数据，覆盖空表、无主键表、复合主键、特殊标识符、长文本和超过一页的数据。
使用多个连接和标签反复切换，证明没有串库、串表、串结果；不拿用户现有业务库做写入验收。

### 第二批：可控的表数据编辑

5. 新增 / 修改 / 删除先进入本地变更集，显示原值、新值、状态和有效变更数。
6. NULL、空字符串、默认值、未输入、自增列、生成列分别处理；仅空白草稿不生成插入语句。
7. 使用主键或已确认唯一键定位，拒绝无法安全定位的修改；SQL 值参数化，标识符按驱动方言引用。
8. 提交前展示 SQL / 参数摘要和受影响范围；只读保护、生产限制、会话身份和修订在后端再次验证。
9. 验证成功提交、约束失败、显式回滚、关闭未提交页、并发更改与取消后状态不确定；事务支持按驱动声明，不伪装通用支持。

这一批完成前，不把“能执行 UPDATE”写成“已支持表格编辑与事务工作台”。

### 第三批：结构设计与文件工作流

10. 字段 / 索引 / 外键 / 触发器按能力显示，变更生成 SQL、提示影响、显式执行；失败后能恢复页面并重新读取结构。
11. 导入按文件预览、列映射、转换、检查、执行、报告组织；覆盖编码、空值、重复键、批次失败和取消。
12. 导出先区分当前结果和全量重新查询；分批读取、可取消、逐格式验证类型和列顺序，不以预览预算冒充完整导出。

之后按原高级路线推进比较同步、诊断、AI 和云备份；每项分别建立真实环境与可重复验收，入口存在不算交付。
继续遵守“不使用浏览器测试，除非用户明确要求”；桌面行为采用 Fyne 控件测试和原生应用操作验证。
